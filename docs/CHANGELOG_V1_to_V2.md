# Changelog — V1 → V2

HADES V1 was an application: a supply-chain risk product with a UI, an API, auth, and a RAG
evidence store. HADES-Bench V2 is a research benchmark. This records what changed, what was
archived, and what was deliberately deferred.

---

## What changed

### The dataset became twelve datasets

V1 shipped one synthetic world. V2 ships **twelve variants** (0, A–K), each isolating one
mechanism so a performance difference is attributable to an identifiable cause. **Variant 0 is
byte-identical to V1** and is the anchor every comparison is measured against.

Three variants carry prerequisites and must not be reported against Variant 0: `A = J + A`,
`D = B + D`, `F = E + F`.

### Ten mechanisms added

| | Mechanism | What it adds over V1 |
|---|---|---|
| A | Partial visibility | observable graph terminates above `max_visible_tier`; the hidden network keeps transmitting |
| B | Hidden shared structure | three types (causal / redundant / decoy) generated by one identical process |
| C | Dynamic relationships | sourcing edges rewire mid-timeline; edge set **and** count both move |
| D | Hidden dependency coupling | `α × mean(co-members' own stress)` — the incremental signal V1's `H_POLYMER` lacked |
| E | Hidden resilience | one latent per supplier, never emitted, inferable from observed history |
| F | Adaptive transmission | attenuation deterministically interpolated from *that same* latent |
| G | Information delay | reporting clock lags the event clock; labels stay on true time |
| H | External shocks | Poisson arrivals with infrastructure-correlated blast radius |
| I | Multi-source dependencies | deterministic AND/OR resolution per component |
| J | Chain-length heterogeneity | upstream supplier tiers with per-chain depth |

### Configuration became first-class

31 parameters, each with a name, numeric default, executable range and description. Out-of-range
values and unknown parameter names abort before generation. Every dataset emits
`resolved_config.json` recording exactly what produced it.

### Output format

CSVs are now **gzip-compressed** (`<table>.csv.gz`, 3.18× measured) in **per-variant directories**
(`db/csv/v<variant>_seed<seed>/`). Determinism survives compression — `mtime=0`, `filename=""` —
and is verified by diffing compressed bytes.

### New table

`supplier_upstream` — Mechanism J's upstream chain, one row per hop, emitted only when both
endpoints survive Mechanism A's truncation. Absent entirely without J.

### Validation became statistical

V1's suite checked structural invariants. V2 adds per-mechanism statistical checks with permutation
nulls, bootstrap CIs and an explicit **gate-versus-report** rule: a check that lacks the power to
mean something at a given configuration reports its numbers and the sample size it would need,
rather than having its threshold weakened.

### Evaluation protocol implemented

`db/benchmark_eval.py`: positional 60/20/20 temporal splits identical across variants, paired
bootstrap CIs, sign consistency, mean/std, and `significant()` applying the spec's full criterion.

## What was archived

Moved to `docs/v1_archive/` with a one-line header. **Nothing was deleted.**

| Document | Why |
|---|---|
| `03_UI_UX_Documentation.md` | 430 lines of screen specs. A benchmark has no user interface. |
| `07_Vector_Database_Design.md` | RAG `evidence_chunks` store. No variant has a retrieval component. |
| `09_REST_API_Documentation.md` | 524 lines of auth and user-admin endpoints. Datasets are gzipped CSVs on disk; there is no dataset-access API. |
| `12_Security_Documentation.md` | JWT, RBAC, encryption for a multi-tenant app. V2 generates synthetic data with no PII and no auth surface. |

Archiving was confirmed before it was done. The alternative — reducing each to a stub — would have
meant documenting tooling that does not exist.

## What was deliberately deferred

Out of scope for V2, **deferred not dropped**:

- Thin-relation parameter-sharing analysis (SHARK)
- Degree-randomization robustness
- Paired HGT checkpoint comparisons
- Shipment anti-smoothing 2×2 experiments

---

## What V1 results still stand

V1 findings are carried forward in `10_AI_ML_Documentation.md` §7 **with their original caveats**.
They are V1 results on the V1 dataset and must not be restated as V2 claims. In particular:

- "Not distinguishable at this label volume" is a statement about sample size, **not** evidence of
  equivalence.
- SHARE's edge over HGT on impact was a **statistical tie**, not a confirmed win.
- Every HGT comparison was **unpaired**.
- SHARK's impact variance remains **unexplained**.

V2 exists partly to resolve these. None of that is validated yet.

---

## Status

**Implemented, not yet run at scale.** All twelve variants generate and validate (60 runs, zero
failures), but only at the 800-supplier `v1` fixture. The spec configuration has never been
generated, label subsampling is not wired into emission, and power targets are met for no task at
any scale actually run. See `PHASE2_PHASE6_IMPLEMENTATION.md` §7.
